# Редакторское ревью комикса в Telegram

## Цель

Ни один выпуск не публикуется, пока Showrunner не увидел конкретный визуальный мастер
и не одобрил именно его. Решение привязывается к SHA-256 изображения, поэтому после
любой правки требуется новое ревью.

## Контур

1. Основной сотрудник завершает `script.md`, мастер и `manifest.json`.
2. Команда `make review-submit ISSUE=issue-NNN` отправляет изображение и карточку в
   приватный редакторский чат.
3. Showrunner нажимает «Одобрить» или «Нужны правки».
4. При запросе правок бот просит ответить сообщением и сохраняет текст комментария.
5. Бот записывает `review.json` рядом с выпуском. В файл не попадают Telegram user ID,
   chat ID, токен и другие приватные идентификаторы.
6. При одобрении статусы `issue.json` и `manifest.json` меняются на `approved`.
7. Ворота публикации проверяют, что хэш в `review.json` совпадает с текущим мастером.

Одобрение не запускает публикацию автоматически. Публикация остаётся отдельным
явным действием после сборки сайта и проверки платформенных адаптаций.

## Запуск

```bash
make review-run
```

Бот использует long polling и может работать на машине с этим репозиторием. Для
первого контура отдельный сервер, webhook и база данных не нужны.
